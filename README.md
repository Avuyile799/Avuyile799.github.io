# Semester 2: SmartStudent Pantry

## Project Overview

SmartStudent Pantry is a student-focused grocery subscription project that aims to help students access affordable groceries. The proposed service provides grocery boxes priced between R500 and R800, with convenient delivery to campus residences.

The project focuses on student food insecurity, affordability and convenience. My portfolio documents the project planning, Agile practices, system design and development activities, together with reflections on what I learned.

## 1. Agile Team Charter

The Agile Team Charter is a living, co-created social contract that defines a team's shared purpose, core values, working agreements and operational boundaries. It helps team members understand their responsibilities and work together towards a common goal.

**My role:** Developer / Analyst.

### Reflection

Creating the Agile Team Charter helped me understand the importance of shared goals, clear responsibilities and communication. The charter also helped me understand how Kanban can be used to track tasks and how working agreements support accountability.

## 2. User Stories and Tasks

A user story in Agile is a short, simple description of a software feature written from the end-user's perspective. It explains who needs a feature, what they want and why it is useful. Each user story is broken down into smaller tasks to make the work easier to plan, complete and monitor.

**My role:** Developer / Analyst.

### Evidence

The following screenshots show examples of user stories, acceptance criteria and task checklists created for the SmartStudent Pantry project. They demonstrate how user requirements were identified and divided into smaller activities.

![User Stories 1](Screenshots/user%20stories%201.png)

![User Stories 2](Screenshots/user%20stories2.png)

![User Stories 3](Screenshots/user%20stories3.png)

![User Stories 4](Screenshots/user%20stories4.png)

### Reflection

Working with user stories helped me understand how to look at a system from the user's perspective. I learned that requirements should be written clearly so that the development team understands what needs to be achieved. Acceptance criteria helped explain what was expected from a particular requirement, while task checklists made it easier to divide the work into smaller steps.

This activity improved my understanding of requirement analysis and planning. I also learned that user stories help connect the needs of students with the features being planned for the system.

Trello also helped me understand the importance of updating tasks and communicating with other team members. I learned that a project board is useful only when the team keeps it updated and uses it regularly to manage its work.
